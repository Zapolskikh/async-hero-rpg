# Async Hero · анимации V3

Рабочий технический риг и движения для простых мужской и женской моделей. Головы/волосы сохранены из V2; корпус, рукава и конечности собраны в непрерывные геометрические формы с плечом, локтем и кистью. Оружие движется вместе с хватом; это не вращение статичного PNG. Этот отдельный демонстратор ещё не встроен в вашу игру.

## Начать здесь

1. Посмотрите `animation_overview.gif`, `storyboard.png` и GIF в `previews/`.
2. Импортируйте `godot/project.godot` в Godot 4.5.1 и запустите. В демонстрации есть пол, выбор всех клипов, пауза, скорость, покадровое перемещение, скелет, отражение и управление фазами каста. Готовый контроллер находится в `godot/actor.gd`.
3. Передайте агенту `AGENT_PROMPT_RU.md` и этот архив вместе с реальным проектом игры. У него будут и движения, и конкретные правила интеграции.

## Что внутри

- 47 клипов для двух профилей: 7 вариантов покоя, мгновенный каст и три фазы чтения для каждого из 7 наборов предметов, удары основной/второй рукой, комбо двух мечей, тяжёлый удар, три фазы лука, три фазы каста посохом, выпад посохом и баш щитом.
- Траектории, сгибы, точки привязки и отрисовка с 60 выборками в секунду; между выборками Actor интерполирует движение.
- 94 прозрачных спрайт-листа по 30 выборок в секунду: `spritesheets/<пол>/<клип>.png`. Ячейка 256×256, 8 колонок, чтение по строкам. Последняя строка может иметь пустые ячейки: число кадров = `ceil(data.clips.frames / 2)`. Для oneshot последний кадр — конечная поза, дальше вернитесь в idle. Для циклов не удерживайте дублированную конечную выборку.
- 47 GIF, в каждом мужчина и женщина рядом. GIF повторяется для просмотра даже у одноразовых действий; это не означает, что клип должен повторяться в игре. GIF использует округлённое время кадра; точный тайминг берите из JSON.
- `data/clips.json`: длительности, зацикливание, события.
- `godot/assets/animations_<пол>.json`: все рассчитанные позы, команды геометрии и сокеты; `right_grip_weight` управляет отпусканием двуручного меча.
- `godot/tests/validate.gd`: проверки воспроизведения и событий.
- `source/build.py`: воспроизводимый генератор; зависимости Python: Pillow и NumPy. Для повторного извлечения голов ему нужны статичные base PNG V2, копии приложены в `source/reference_v2/`.

## API

`actor.instant_cast("greatsword")` — краткий каст с отпусканием правой кисти.

`actor.begin_cast("sword")` → ожидание игрового таймера → `actor.release_cast("sword")`.

`actor.interrupt_cast("sword")` — отмена без выпускания заклинания.

`actor.play_clip("dual_combo", "idle_dual")` — действие и автоматический возврат.

Для лука: `play_clip("bow_draw", "bow_hold")`, затем `play_clip("bow_release", "idle_bow")`.

Для каста посохом: `play_clip("staff_cast_begin", "staff_cast_hold")`, затем `play_clip("staff_cast_release", "idle_staff")`.

Сигнал `action_event` передаёт имя события, сокет и его мировой Transform2D. Нанесение урона, снаряды, частицы, аудио и баланс подключаются вашей игрой. Не создавайте урон дважды, если симулятор уже его рассчитывает.

## Границы комплекта

Это техническая реализация на Node2D с отрисовкой геометрии и текстурой головы, а не экспорт из Spine и не готовые ресурсы Skeleton2D/AnimationPlayer. Код рига и данные открыты и приложены. Движения переносятся на Bone2D по инструкции, если такой подход лучше подходит проекту.

Базовые оружия входят в отрисовку клипов. Набор всех индивидуальных вещей вашего инвентаря не приложен; при интеграции агент должен заменить геометрию предметов на ваши изображения с корректными точками хвата. Полноценная подгонка каждой брони также требует слоёв под соответствующие кости.

Не обещается студийная покадровая ручная анимация: промежуточные движения рассчитаны из заданных траекторий и ограничений. Цель этого комплекта — проверить правильную механику и дать агенту воспроизводимый рабочий пример.
