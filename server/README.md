# Сервер Async Hero RPG

Сервер авторитетный: клиент присылает намерения («нанять», «начать поход»), а правила игры решают, что произошло. Логика не дублируется: сервер запускает те же правила на GDScript, что и клиент, через пул процессов Godot без окна.

```
клиент (Godot, веб/телефон/ПК)
   │  HTTPS, JSON
   ▼
Caddy (HTTPS-сертификат) ──► FastAPI (server/app)
                               │  ├─ PostgreSQL: аккаунты, профили, снимки героев, награды за найм, журнал
                               │  └─ пул Godot-воркеров (worker/worker.gd → scripts/core/rules.gd)
```

## Что уже есть

- **Гостевые аккаунты.** Токен хранится на устройстве, в базе лежит только его хеш. Привязку Steam/Google/Apple можно добавить потом поверх той же таблицы `accounts`.
- **Профиль на сервере.** Золото, коробки, лут и походы считает сервер. Состояние генератора случайных чисел (RNG) хранится в профиле и не уходит клиенту, поэтому исход коробок и дропа нельзя предсказать.
- **Походы без тика.** При старте поход один раз симулируется в таймлайн наград, дальше награда зависит только от прошедшего времени. Фарм ограничен 12 часами после последнего сбора.
- **Асинхронный мультиплеер.** На доске до 3 из 6 мест занимают снимки реальных игроков вашего уровня ±3, остальное заполняют NPC гильдии (танк и лекарь есть всегда). Первыми показываются те, кого сегодня нанимали меньше всех.
- **Награда за найм.** Владелец получает 5% золота с походов, где был его герой, и счётчик «вас наняли N раз». Награду создаёт система, у нанимателя ничего не забирается. Есть лимиты: 3000 золота в день на владельца и 30 событий в день на пару «владелец–наниматель». Выплата приходит при следующем входе владельца.
- **Защита:**
  - проверка каждого действия правилами;
  - служебные действия (выдача наград) недоступны клиенту;
  - блокировка профиля на время запроса;
  - журнал действий с золотом до и после;
  - ограничение частоты запросов;
  - CORS.
- **Рейтинг** по прогрессу кампании и самые нанимаемые герои.

## Локальный запуск

Нужны Python 3.11+ и Godot 4.5 (обычный, не .NET).

```bash
cd server
pip install -r requirements.txt
GODOT_BIN=/путь/к/godot ./run_local.sh          # http://127.0.0.1:8000, база SQLite
```

В игре: шестерёнка → «Адрес сервера» `http://127.0.0.1:8000` → «Подключиться».

Тесты (настоящие воркеры и база):

```bash
pip install -r requirements-dev.txt
GODOT_BIN=/путь/к/godot python -m pytest -q tests                       # SQLite
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@host/db python -m pytest -q tests  # Postgres
```

Сквозной тест клиента против запущенного сервера:

```bash
godot --path .. -- --online-test=http://127.0.0.1:8000 --shots=/tmp/shots
```

## Развёртывание на VPS

Подойдёт любой сервер с Ubuntu 22.04/24.04 на 2 vCPU и 2–4 ГБ памяти, например Hetzner CX22 примерно за 5 € в месяц. Нужен домен или поддомен, например `api.ваш-домен.ru`.

1. **DNS.** Создайте A-запись `api.ваш-домен.ru` → IP сервера.
2. **Docker** на сервере:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **Код и настройки:**
   ```bash
   git clone https://github.com/Zapolskikh/async-hero-rpg.git
   cd async-hero-rpg/server
   cp .env.example .env
   nano .env      # DOMAIN, POSTGRES_PASSWORD, CORS_ORIGINS
   ```
4. **Запуск:**
   ```bash
   docker compose up -d --build
   curl https://api.ваш-домен.ru/health     # {"ok": true, ...}
   ```
   Caddy сам получит HTTPS-сертификат. Порты 80 и 443 должны быть открыты.
5. **Подключить игру.** Откройте `https://zapolskikh.github.io/async-hero-rpg/?server=https://api.ваш-домен.ru`: адрес подставится сам. Можно и вручную: шестерёнка → адрес → «Подключиться».

Веб-версия на GitHub Pages открывается по HTTPS, поэтому сервер тоже должен быть на HTTPS, иначе браузер заблокирует запросы. Для локальных тестов это не нужно.

### Обслуживание

```bash
docker compose logs -f api                                   # логи
git pull && docker compose up -d --build                     # обновление
docker compose exec db pg_dump -U hero hero > backup.sql     # резервная копия
docker compose exec -T db psql -U hero hero < backup.sql     # восстановление
```

Схема базы создаётся автоматически при старте. Когда схема начнёт меняться на живых данных, стоит подключить Alembic для миграций.

## API

Авторизация: `Authorization: Bearer <token>`.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/v1/auth/guest` | `{"name": "Олег"}` | `account_id`, `token` + вид профиля |
| GET | `/v1/me` | — | вид профиля: завершает штурмы, выплачивает награды за найм |
| POST | `/v1/action` | `{"action": "...", "args": {...}}` | вид профиля + `result` |
| GET | `/v1/leaderboard` | — | число игроков, топ кампании, самые нанимаемые |
| GET | `/health` | — | `{"ok": true}` |

Вид профиля: `{ok, error, result, reports, profile, pending, server_time}`.

Действия:
- **локальные** (клиент применяет сразу, сервер подтверждает): `set_rotation`, `move_party`, `equip`, `unequip`, `sell`, `hire`, `fire`, `replace`, `fuse`, `set_name`;
- **только на сервере** (клиент ждёт ответа): `reroll`, `open_box`, `open_pack`, `start`, `collect`, `stop`.

Список действий и их аргументы описаны в `scripts/core/rules.gd`.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DATABASE_URL` | `sqlite+aiosqlite:///./hero.db` | база (`postgresql+asyncpg://...` в проде) |
| `GODOT_BIN` | `godot` | путь к Godot |
| `PROJECT_DIR` | корень репозитория | где лежат `project.godot`, `scripts/`, `worker/` |
| `WORKERS` | 2 | сколько процессов Godot (≈ по одному на ядро) |
| `CORS_ORIGINS` | `*` | откуда разрешены запросы (адрес клиента) |
| `ASSIST_DAILY_GOLD_CAP` | 3000 | максимум золота за найм на владельца в день |
| `ASSIST_PAIR_DAILY_EVENTS` | 30 | лимит событий «владелец ← наниматель» в день |
| `POOL_LEVEL_RANGE` | 3 | разброс уровней для доски наёмников |
| `RATE_PER_SEC`, `RATE_BURST` | 8, 30 | ограничение запросов на аккаунт |

## Производительность

Действие в воркере занимает около 2 мс, старт похода с расчётом таймлайна — около 10 мс. Двух воркеров хватает на сотни активных игроков: игроки делают мало запросов, а между запросами сервер ничего не считает.
